About

I came to infrastructure through mathematics. Two years of proofs taught me to distrust anything I couldn't check, and that habit followed me into the cloud: an alert that fires every morning is noise, a backup nobody has restored is a hope, and a module copied between repositories is a future incident.

Today I work on a data platform on Google Cloud, after a year on AWS workloads at EDF. I like the unglamorous parts of the job: writing the Terraform module that ten projects will reuse, tuning an alert until it means something, writing the post-mortem so the same thing never wakes anyone up twice.

“If it isn't tested, it isn't a backup. If it isn't in code, it isn't infrastructure.”

Selected projects

Side projects and open-source work, written up the way I'd explain them in an interview.

i.

Open-source Helm chart

pgkube-guard

Most teams back up their databases but never test the restore. pgkube-guard backs up PostgreSQL to S3 every night, restores each dump into a throwaway database to prove it works, and alerts the team the moment a backup or a restore fails.

Context
Untested backups are the classic silent failure, discovered on the worst day.
Architecture
Kubernetes CronJobs → pg_dump to S3 → restore job into an ephemeral database → validation queries → alerting.

  • Helm
  • PostgreSQL
  • S3

ii.

Self-hosted Kubernetes

keda-observation

Event-driven autoscaling of a Kafka → PostgreSQL pipeline on my own Kubernetes cluster running on Hetzner VMs, deployed with GitOps and monitored end to end.

Context
Consumers sized for the peak waste resources the rest of the time. Scaling on queue lag instead of CPU fixes that.
Architecture
Kafka topic → Go consumers scaled by KEDA on consumer lag → PostgreSQL. ArgoCD syncs manifests; Prometheus & Grafana watch it all.
